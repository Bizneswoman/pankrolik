# RCA — "Pan Królik" admin shows empty tabs in production

Deployment: `elegant-rabbit` (31d72328-…)  ·  Active run: `a40d32c7-f9ce-4e21-8963-9710c5fbc101` (type=initial, status=success)
Live URL: https://elegant-rabbit.emergent.host  ·  Template: nextjs_mongo_shadcn_base_image · frontend=kubernetes · tier_0

## TL;DR
Production is **healthy server-side** — the DB is fully populated and all four `/api/*` endpoints return HTTP 200 with real data. The reported "empty tabs" is **NOT** caused by an empty/partial DB, a broken API, a bad secret, or an unbound DB. It could not be reproduced against the live URL; the evidence points to a **client-side cause** (stale cached admin bundle and/or the owner viewing `pankrólik.pl`, which is **not linked to this deployment**). Separately, two real defects were confirmed: **`public/` static assets 404**, and the **preview data did not migrate — production is running the stock seed defaults**.

## 1. Is the latest code built & deployed? (safeContent / seed v5)
- There is exactly **one** deploy run and it **succeeded**. The live image is that run — the deploy is **NOT stale and did NOT fail**.
- I could **NOT directly verify the source** contains `safeContent` (admin/page.js) or `version: 5` (lib/seed.js): the eph sandbox failed to boot 3× (`eph_spawn_failed: pod reached terminal phase "Failed"` — platform-side), and `get_build_logs` returned `build_lookup_limit`. **Source-content verification = UNVERIFIED.**
- Indirect signal: the production `content` doc contains `footer`, `social`, and `about.features` — the exact fields migration v5 backfills — which is *consistent* with v5 logic having run, but is not conclusive (those fields could have pre-existed).

## 2. Production MongoDB binding + contents
- **Binding OK.** `MONGO_URL`, `DB_NAME`, `NEXT_PUBLIC_BASE_URL`, `REACT_APP_BACKEND_URL`, `CORS_ORIGINS`, `INTEGRATION_PROXY_URL` all present/non-empty. Resolved db: `elegant-rabbit-your_database_name`. APIs read/write fine.
- **Counts:** `content`=1, `menu`=**30**, `gallery`=**20**, `reviews`=3. Collections present: content, gallery, menu, reviews.
- **content doc fields:** hero ✓, about.features ✓ (4 items), contact.hours ✓ (3 rows), social ✓, footer ✓ — all present.
- **`meta.version`: NOT FOUND.** There is **no `meta` collection**, and the single `content` doc (id="site") has no version field. Whatever is supposed to record migration version is not being persisted to this DB. Worth checking where `seed.js` writes `meta.version` — if it never persists, migrations lose their completion marker.
- **IMPORTANT — preview data did NOT carry over.** Preview = menu 0 (intentionally empty), gallery 5 (curated). Production = menu **30**, gallery **20**, and every value is **distinct** (no duplication). These are the **stock DEFAULT seed images/dishes** (pexels/unsplash defaults), not the owner's curated preview content. So the preview→prod migration did not bring the owner's data; `ensureSeed()` filled the empty prod collections with defaults instead.

## 3. Static assets on the live domain

NOTE: the gallery tab itself uses remote unsplash/pexels URLs from the DB, so this 404 affects the logo and local `/gallery/*.jpg` / `/about.jpg` only — it is a separate cosmetic defect, not the empty-tabs cause.

## Why the owner likely sees "one tab works, the rest empty"
Since every API returns data on the live URL, the leading hypothesis is **client-side**: the Content tab renders from the initial server payload (works), while Menu/Gallery/Reviews load via client-side fetch that is failing **in the owner's browser/host** — most consistent with a **stale cached admin bundle** or the owner viewing **`pankrólik.pl`, which is NOT attached to this deployment** (`list_domains` = empty) and may resolve to an old/preview host. This matches "one tab works and everything else is empty" exactly. This part is a hypothesis — it could not be reproduced server-side.

## Recommended fixes
- **User — verify the real endpoint:** Hard-refresh / open incognito on `https://elegant-rabbit.emergent.host/admin`, open DevTools → Network/Console, and capture what the Menu/Gallery/Reviews tabs request and the exact error. Confirm which host is actually being viewed.
- **User — domain:** `pankrólik.pl` is not linked to this deployment. Link it in Deployment Panel → Domains (and point DNS) if it's meant to serve this app; otherwise the owner may be on a stale/old host.
- **Code (E1) — static assets:** Ensure the Next.js standalone build ships `public/` (so `/logo-transparent.png`, `/gallery/*.jpg`, `/about.jpg` return 200). Currently `.next/static` ships but `public/` 404s.
- **Code (E1) — seed/migration tracking:** No `meta` collection / no `meta.version` persisted. Verify `seed.js` actually writes the version marker so migrations are tracked/idempotent.
- **Code/Data (E1) — preview data not migrated:** Production is running stock seed defaults, not the owner's preview content (menu 0→30, gallery 5→20). If the owner expected their curated preview data in prod, the preview→prod copy needs to be redone (DB Manager) — seed defaults filled the empty collections instead.
